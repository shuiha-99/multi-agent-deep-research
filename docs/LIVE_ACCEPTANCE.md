# 真实在线验收

`scripts/acceptance_live.py` 是显式运行的在线验收入口，会实际调用本项目 `.env` 配置的对话、搜索和向量服务并产生相应费用。它需要支持 Search/COSINE 的 Redis，不能用离线示例或 mock 代替。

```powershell
.venv/Scripts/python.exe scripts/acceptance_live.py
# 也可分阶段执行，避免重复调用已通过的真实服务：
.venv/Scripts/python.exe scripts/acceptance_live.py --stages tools
.venv/Scripts/python.exe scripts/acceptance_live.py --stages comprehensive,cancel_retry,recovery
.venv/Scripts/python.exe scripts/acceptance_live.py --stages cache
```

脚本启动自己的本机 API 进程，默认端口 8125；数据写入 `.cache/live-acceptance/<run_id>/`，结果写入 `artifacts/acceptance/<run_id>/`。它不连接或关闭现有 8000 服务，不修改 `.env`，不清空 Redis，不展示密钥。退出时仅关闭自己创建的进程。进程使用每项研究 18 次模型、36 次工具的既有默认预算；工具请求上限 60 秒、整项研究上限 600 秒。

| 阶段 | 实际检查 |
| --- | --- |
| `tools` | 九个真实业务工具、Tavily 结果、Redis 知识检索、原文/元数据、公开网页正文与表格、模拟订单的真实统计和 PNG；未选数据集会失败并记录事件 |
| `comprehensive` | 真实主智能体分别委派三个助手；报告、真实 web 来源、1024 维知识检索链路、程序统计与图表；核对 3900 销售额、3720 净销售额、16 订单及模拟标识 |
| `cancel_retry` | 在真实模型请求进行时取消任务；原任务保持取消，重试产生新任务；新任务只使用 data 助手并完成统计与报告 |
| `recovery` | 数据助手完成、主模型汇总时强杀自身进程；等待旧 Redis 租约自然过期后重启；同任务 attempt=2、检查点续跑、已完成业务工具调用不重复（计数按实际观测） |
| `cache` | 原固定 12 查询序列；关闭前置精确缓存，独立报告精确探针、语义命中、错命中、直连与完整缓存路径耗时 |

综合图可按问题需要选择工具；九项能力由独立工具阶段覆盖。公开 Python CSV 文档用于核查数据处理技术，不能作为咖啡市场证据。经营数据和产品资料是明确标注的模拟样例，统计计算是真实执行；不能据此推断真实店铺或市场结果。

每个阶段独立写入 `result.json`，失败也保留已有证据。`functional_passed` 只汇总功能检查；`passed` 还要求参考图片中的 30 倍与 30%—50% 性能目标通过。脚本不会调整阈值、挑选结果或添加模拟网络等待以凑指标；即使功能通过，性能目标仍可能未达到。原始缓存结果另保存为 `cache-evaluation.json`。真实连续智能体任务的运行记录和固定工具查询层性能结果应分开解释。

检查点是步骤边界恢复。若进程在外部调用完成、检查点保存前被终止，恢复可能重复调用；本用例选择已完成数据工具持久化后的边界，不宣称任何中断点都能做到恰好一次。
