# 固定查询序列的缓存评测

`evals/cache_cases.json` 固定了 12 条外部查询的顺序，包含同义改写、日期、地区、实体、意图及同范围不同指标的负例。每条查询有预标注等价组；不同组之间复用算错命中。该集合用于评测，阈值校准应使用另外的集合，不能依据本次结果删选查询或反复调参后仍称独立评测。

```powershell
.venv/Scripts/python.exe scripts/evaluate_cache.py --mode demo
# 配置本地 .env 后执行；这条命令会调用真实搜索、embedding 和 Redis。
.venv/Scripts/python.exe scripts/evaluate_cache.py --mode live
```

每次运行使用新的评测命名空间，不清空用户缓存；在线评测写入的 Redis 数据按配置 TTL 过期。业务 SQLite 和离线缓存隔离在 `.cache/cache-eval/`，报告分别写入 `artifacts/cache-eval/demo/` 或 `artifacts/cache-eval/live/`。脚本不会读取其他应用的密钥，也不会输出服务密钥。

每条查询创建独立任务以验证来源登记，但没有调用主智能体或助手；这是**工具查询层评测**。它复用生产搜索适配器，在线模式使用实际搜索和 embedding。离线模式使用字符特征哈希和虚构网页，不人为添加网络等待，因此缓存可能比直接读取更慢。

语义专项关闭精确缓存查询，分母为固定集中所有实际执行语义检索的查询。脚本另做只读精确探针，探针不计入语义分子、分母和耗时。不会把精确探针的命中率写成组合缓存的命中率。

对每条命中，脚本用同一查询再直连一次搜索服务；命中路径计入 embedding、向量查询、反序列化和当前任务的来源登记。仅对预标注组一致的正确命中汇总 `直连接口平均耗时 / 缓存完整命中路径平均耗时`，并保留逐条耗时、中位数、P95 和两个固定窗口的结果。样本量较小时，这些值只用于检查流程，不能证明性能稳定。

报告包含固定集 SHA-256、时间、Python/系统信息、embedding 名称与维度、阈值、TTL、精确探针、语义命中率、误命中、漏命中和逐请求记录。退出码为 0 表示运行结束且没有预标注错命中，2 表示出现错命中，1 表示配置或运行失败；命中率低并不会伪装成通过截图性能目标。

2026-10-30 已执行一次示例评测：12 次语义查询、2 次命中、0 次预标注错命中。字符哈希未识别出部分语义等价改写，不能据此声称神经语义检索效果；该次命中路径约为直接离线读取耗时的 4.8 倍，也不能推断真实 API 的加速情况。原始报告位于 `artifacts/cache-eval/demo/803d13361e954f308fc703cca5611aa3.json`。

完整的截图指标仍须补充真实模型驱动的连续研究任务、独立阈值校准集、更大的预先固定批次、过期缓存案例和实际接口验证。应额外报告真实搜索请求减少量、模型用量与整任务耗时；来源存在、标签一致和搜索摘要可复用都不能代替人工事实核验。30 倍与 30%—50% 仍为未达成验证的目标。
